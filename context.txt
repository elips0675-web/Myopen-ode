PURPOSE
-------
Local AI coding assistant that replaces cloud-based tools.
Runs entirely offline on RTX 3060, powered by Ollama + DeepSeek/qwen models.
User types a task in browser, model calls tools to read, edit, write, run code.

KEY ACHIEVEMENT
---------------
- Prompt-based tool calling: local models do NOT support native tool_calls in Ollama.
  Engineered a working agent loop: model outputs ```tool blocks, backend parses, executes, feeds back.
- 25 tools: read, write, edit, bash, glob, grep, list, web, websearch, diff, commit, undo,
  verify, plan, search, question, skill, patch, task, todo, lsp, testgen, db_query + plugins
- Sessions: full session management with save/load to .agent_sessions/*.json
- RAG: hybrid search (BM25 + semantic) with incremental per-file disk cache
- Self-hosted, zero-cost, fully offline alternative to Cursor/Claude Code
- Feature parity ~90% with OpenCode Desktop (per Kimi evaluation 8.8/10)

ARCHITECTURE
------------
Modular: agent.py (FastAPI) + tools.py (25 tools) + rag.py (hybrid RAG) +
lsp.py (LSP client) + ui.py (inline HTML UI) + mcp_server.py (MCP for IDEs) +
desktop.py (pywebview native window). Zero npm deps, only fastapi+uvicorn+requests.

1. FastAPI server on port 8765, OpenAPI docs at /docs
2. HTML UI served at GET / (inline, no npm, no build tools)
3. POST /api/chat — SSE streaming endpoint with session support
4. Agent loop: up to 12 iterations, 60s timeout, 3 retries, auto-execute fallback
5. File versioning: backups in .agent_backups before every write/edit/save (up to 50 versions)
6. Verify step: py_compile for .py, tsc --noEmit for .ts/.js, json.tool for .json
7. Git integration: diff + auto-commit
8. Context management: auto-summarization every 3 iterations via 1.5b model
9. RAG: hybrid BM25 + cosine similarity, incremental per-file cache (.rag_cache/)
10. Sessions: full CRUD (create, list, load, delete, export/import JSON)
11. Multi-project: projects.json, per-project sessions/RAG/memory
12. LSP: definition, references, hover, symbols, rename (pylsp/ts-ls/gopls)
13. MCP server: all 25 tools via Model Context Protocol (VS Code/Cursor/Claude Desktop)
14. Plugins: .agent_plugins/*.py — dynamic tool registration

SAFETY
------
- Directory traversal protection (read/write/edit/patch outside WORK_DIR blocked)
- Bash sandbox: blacklist of dangerous commands
- Confirmation before write/edit/bash/commit/undo (with UI buttons)
- Retry with exponential backoff (3 attempts)
- Path validation for glob/grep/list
- NO_CONFIRM=1 skips all confirmations

PERFORMANCE
-----------
- eval_count token counting, in-loop summarization every 3 iterations
- Incremental RAG cache: only changed files re-embedded
- Hybrid search: BM25 (Okapi k1=1.5 b=0.75) + cosine similarity (0.4 weight)
- LLM cache with TTL (LLM_CACHE_TTL=60s, max 100 entries)
- Configurable AGENT_TIMEOUT / AGENT_MAX_ITER / AGENT_MEMORY_LIMIT / bash timeout

HOW AGENT LOOP WORKS
--------------------
1. System prompt tells model it has tools and must output ```tool blocks
2. Model responds: text + ```tool {"tool":"read","path":"file.py"}
3. Backend parses JSON, validates schema, executes tool, appends result as user message
4. Model gets result, decides next step (read more, edit, verify, commit)
5. Loop ends when model responds without a tool block
6. Fallback: if user says "yes"/"да" and no tool block found, auto-executes pending tool

MODELS
------
Primary: deepseek-r1:7b or qwen2.5-coder:7b (RTX 3060, ~5.5GB VRAM)
Planner: deepseek-r1:1.5b (PLANNER_MODEL)
