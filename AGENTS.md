# AGENTS.md — обязательные правила для этого проекта

## Промпт-система агента (справочник для ИИ — копировать эти правила при работе над агентом)

Многоуровневая система промптов (~8 блоков). Агент использует гибрид:
legacy (```tool JSON) для старых моделей, native (tool_calls) для
qwen3/llama3.1/gpt-oss, сабагенты для ревью/фиксов. Точное расположение в коде:

1. **SYSTEM_PROMPT** (legacy, правила 1–23, ~2K токенов) — `tools/__init__.py:37`.
   Принуждает строгий JSON в ```tool блоках. Ключевые: один тул за ответ,
   [DONE] для завершения, код только через write/edit, read перед edit,
   никогда не выдумывать пути, повторять точный блок после «yes»,
   внешние папки — полными путями (rule 22), ревью через task(agent='reviewer')
   → потом fixer (rule 23).
2. **COMPACT_SYSTEM_PROMPT** (KV-cache) — `tools/__init__.py`, включается
   автоматически при it >= 3 (core/agent_loop.py:186) — экономия ~1.7K токенов.
3. **NATIVE_SYSTEM_PROMPT** — `tools/llm.py` (для моделей с tool_calls):
   без правил про ```tool-блоки, «используй ВЫЗОВЫ ФУНКЦИЙ, а не текст»,
   код только через write/edit.
4. **SUBAGENT_PROMPTS** — `tools/__init__.py:263` (reviewer/fixer/general/
   explore/scout). Активация: маркер `@reviewer/@fixer/@general` в первом
   сообщении (agent.py `_apply_subagent_marker`, этап 54) или тул `task`
   (tools/exec.py `_tool_task`). Reviewer выдаёт CRITICAL/WARNINGS/VERDICT,
   fixer чинит по одному и перепроверяет.
5. **Динамический контекст** — `core/agent_loop.py` `_dynamic_context()`
   (вставляется перед каждым вызовом LLM): проект, итерация, последний тул +
   статус, ошибки сессии, глобальная статистика тулов с советами.
6. **TOOL_SCHEMAS** — `tools/_state.py` (30 тулов; json-схема edit:
   path/old/new). Lenient-парсер (этап 37) принимает значения без кавычек.
7. **Маркеры**: `[DONE]` (цикл прерывается), `@reviewer/@fixer/@general`
   (подмена системного промпта), `[PLAN]` (дерево задач в UI, этап 31).
8. **Критично для полноценной работы**: retry с temp=0.1 при мусоре,
   парсинг «голого» JSON без ```tool, nudge-система («код → в write», макс 2 раза).

Любые правки этих промптов: обновлять этот раздел, не ломать
test_system_prompt_rules и 115+ тестов, синхронизировать README/TODO/context.

## Документация (ОБЯЗАТЕЛЬНО после любых изменений)

1. После КАЖДОГО изменения кода (фикс, фича, рефакторинг) — обновить ДОКИ в том же шаге:
   - `README.md` (RU + EN разделы) — фичи, инструменты, тесты, установка
   - `TODO.md` — отметить сделанное [x], убрать/перенести пункты, добавить новые
   - `context.txt` — статус, фиксы, баги, модели, счётчики
2. Синхронизировать числа и факты между доками и кодом:
   - количество инструментов (схемы в `tools.py` TOOL_SCHEMAS + плагины `.agent_plugins/`)
   - количество тестов (`python test_agent.py` — актуальное число)
   - оценки в README/context — сверять с файлами `Оценка *.txt` (Kimi 7.8, DeepSeek 9)
   - список коммитов/что сделано
3. Перед коммитом: `git status` — в коммит должны входить и доки, и код (один коммит = код + доки).
4. Проверка перед пушем: `python test_agent.py` (все тесты зелёные), `python -m py_compile <изменённые файлы>`.
5. Не хранить устаревшие копии кода в репо (папка `test/` — кандидат на удаление).

## Чистота репозитория

1. В git только исходники и доки. НЕ трекать: бинарники (`AI Desktop.exe`), локальные данные (`projects.json` — автосоздаётся при старте), устаревшие прототипы (`chat.html` удалён), копии кода для ревьюеров (`test/` удалена), логи/кэши (`*.log`, `*.err`, `.rag_cache/`, `.agent_sessions/`, `.agent_memory/`, `.agent_backups/`, `__pycache__/`).
2. .gitignore держать актуальным при добавлении новых артефактов (exe, json-данные, кэши).
3. Перед коммитом: `git status` — не должно быть лишних/служебных файлов в стейдже.
