2. Что можно допилить сверх TODO (рекомендации)
🖥️ Интерфейс и UX
Встроенный редактор с подсветкой и автодополнением – сейчас только просмотр файлов. Хорошо бы добавить Monaco Editor (или CodeMirror) с возможностью редактирования и сохранения через Ctrl+S, а также автодополнение путей/символов через LSP.

Вкладки для нескольких открытых файлов – как в IDE, чтобы одновременно смотреть код и чат.

Интерактивный терминал – встроенный терминал для bash-команд с историей и возможностью прерывания (Ctrl+C).

Поддержка жестов и клавиатурных сокращений – например, Ctrl+Enter для отправки, стрелки для истории сообщений.

⚙️ Функциональность
Глубокий анализ зависимостей – автоматическое чтение requirements.txt, package.json, go.mod и предложение установки недостающих пакетов перед сборкой.

Генерация тестов – инструмент testgen для автоматического создания unit-тестов на основе кода.

Рефакторинг с переименованием – rename с обновлением всех ссылок (через LSP rename).

Поддержка баз данных – инструмент db_query для выполнения SQL-запросов к локальной БД (SQLite, Postgres) и возврата результатов в структурированном виде.

Интерактивный дебаггер – возможность поставить breakpoint в коде и пошагово выполнять с просмотром переменных (через pdb/debugpy).

🚀 Производительность и масштабирование
Инкрементальная индексация RAG – отслеживать изменения файлов (inotify) и обновлять эмбеддинги только для изменённых файлов, а не перестраивать всё при каждом запуске.

Гибридный поиск (BM25 + semantic) – улучшить search, добавив ранжирование по TF-IDF в дополнение к косинусному сходству.

Кеширование вызовов LLM – для одинаковых запросов (например, повторная проверка синтаксиса) использовать кеш с TTL, чтобы не тратить токены и время.

Поддержка GPU-ускорения для эмбеддингов – если Ollama не использует GPU для nomic-embed-text, можно переключиться на sentence-transformers через ONNX.

🔒 Безопасность
Изоляция bash-команд в Docker-контейнере – чтобы даже при NO_CONFIRM=1 команды выполнялись в изолированной среде с ограниченным доступом к файловой системе.

Поддержка политик безопасности – возможность определить, какие инструменты разрешены для каждого проекта (например, запретить bash для внешних репозиториев).

Аудит действий – логирование всех выполненных инструментов с возможностью просмотра истории изменений (кто, когда, что делал).

🧪 Разработка и тестирование
Полное покрытие юнит-тестами – сейчас 11 smoke-тестов, нужно добавить тесты для каждого инструмента с моками, а также для агент-лупа, парсинга, безопасности.

Интеграционные тесты с реальной Ollama – запуск тестовой модели (например, tinyllama) и проверка сквозных сценариев.

CI/CD для автоматического релиза – сборка Docker-образа, публикация на GitHub Releases с готовым исполняемым файлом (PyInstaller) и десктоп-сборкой.

🌐 Экосистема
Реестр плагинов – публичный репозиторий с .agent_plugins/*.py, чтобы пользователи могли шарить свои инструменты (как npm).

Поддержка MCP-серверов извне – возможность подключать внешние MCP-серверы (например, для работы с Jira, Slack) через конфиг.

Интеграция с GitLab/GitHub – автоматическое создание PR/MR после коммита, возможность комментировать код в репозитории.

Документация API в формате OpenAPI – добавить fastapi.openapi() и сгенерировать Swagger UI для упрощения интеграции.
