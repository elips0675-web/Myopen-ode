Оценка проекта «AI Coding Agent» (My OpenCode)
Общая характеристика
Проект представляет собой полнофункционального локального AI-агента-программиста, работающего полностью офлайн на связке Ollama + qwen2.5-coder:7b. Код написан на Python, занимает один файл (agent.py, ~500 строк) и разворачивается через FastAPI с веб-интерфейсом. Основная цель – заменить облачные инструменты вроде Cursor или Claude Code, предоставив бесплатного и приватного помощника для повседневных задач разработки.

1. Архитектура и дизайн
Сильные стороны:

Монолитная архитектура компактна и проста для понимания.

Использование FastAPI с SSE-стримингом – современно и эффективно для чат-интерфейса.

Реализован prompt-based tool calling – остроумное решение, поскольку qwen2.5-coder:7b в Ollama не поддерживает нативные tool_calls. Агент парсит блоки tool, исполняет их и возвращает результат обратно в диалог.

Встроена автосуммаризация контекста (через qwen2.5-coder:1.5b) при превышении 4 000 символов – это позволяет работать с длинными сессиями без потери важной информации.

Поддерживается 32 000 токенов контекста (расширено с 8К) – ощутимый плюс для сложных задач.

Недостатки:

Отсутствует управление сессиями – HTTP-запросы stateless, история теряется после перезагрузки страницы. Для постоянной работы это критично.

Глобальные переменные (RAG_INDEX, RAG_CHUNKS) и смешение логики в одном файле – со временем усложнит поддержку.

Много синхронных операций (запросы к Ollama, выполнение инструментов) – при высокой нагрузке могут блокировать цикл событий.

2. Инструментарий (14 инструментов)
Набор инструментов продуман и покрывает основные сценарии:

Чтение/запись/редактирование файлов – с поддержкой абсолютных путей и URL.

Bash – позволяет выполнять команды, с поддержкой рабочей директории.

Поиск (glob, grep) – гибкие маски, поиск по содержимому.

Git – diff и commit – упрощает версионирование.

Планирование – инструмент plan предлагает пошаговый план, который пользователь подтверждает.

Верификация – автоматическая проверка синтаксиса .py, .js/.ts, .json после изменений.

RAG (search) – семантический поиск по кодовой базе через Ollama embeddings – полезная фича для быстрой навигации.

Что можно улучшить:

grep использует внешнюю утилиту rg – стоит сделать fallback на встроенный поиск Python, если ripgrep не установлен.

web и read с URL ограничены 5000 символов – для больших страниц нужно докачивать или предлагать обрезать.

diff показывает полный вывод – лучше показывать только изменённые строки с контекстом (структурный diff).

3. Безопасность и надёжность
Защитные механизмы:

Бэкапирование перед каждым write/edit – до 50 версий хранятся в .agent_backups, доступен undo.

Подтверждение перед деструктивными операциями (write, edit, bash, commit, undo) – предотвращает случайные действия.

Таймаут на выполнение агента (60 секунд) и 3 попытки парсинга JSON – защита от зависаний.

JSON Schema-валидация всех tool-вызовов – отклоняются некорректные запросы.

Верификация синтаксиса после записи – дополнительный барьер.

Потенциальные риски:

Подтверждение работает только по ключевым словам (yes, y, etc.) – можно уточнить распознавание.

Нет ограничения на размер загружаемых файлов и вывода инструментов – возможно переполнение памяти при обработке больших файлов.

RAG индексирует только ограниченное количество расширений и файлов – для больших проектов может не хватить.

4. Производительность и оптимизация
Основная модель 7B работает на RTX 3060 (~47 ток/с) – вполне достаточно для интерактивной работы.

Автосуммаризация и RAG используют более лёгкую модель 1.5B – это разумно для экономии VRAM.

Время ответа приемлемое, но при сложных цепочках инструментов (12 итераций) может достигать предела таймаута.

Нет кэширования эмбеддингов RAG между запросами – пересчитывается при каждом обращении (хотя индекс обновляется редко).

5. UI/UX
Веб-интерфейс полностью встроен в один HTML – нулевая зависимость от npm. Приятные особенности:

Подсветка синтаксиса diff (зелёное/красное).

Тёмная тема с сохранением в localStorage.

Кнопка отмены запроса (AbortController).

Статус подключения к Ollama.

Возможность переключения модели на лету.

Что можно улучшить:

Отсутствует индикация прогресса выполнения нескольких инструментов.

Нет возможности прервать отдельный инструмент, только весь запрос.

Сообщения не группируются – поток ответа может быть перегружен техническими деталями.

6. Документация и тестирование
Документация:

README.md – краткое руководство, список инструментов, архитектура.

context.txt – подробный обзор проекта с ключевыми достижениями и сравнением с аналогами.

TODO.md – прозрачный список сделанного и планов.

Код содержит комментарии, но не везде.

Тестирование:

Есть test_agent.py с 11 smoke-тестами (читает, пишет, редактирует, bash, glob, URL и т.д.) – тесты проходят.

Отсутствуют unit-тесты для отдельных функций и интеграционные тесты с реальной Ollama – это слабое место.

7. Инновационность и ценность
Главная инновация – обход отсутствия native tool_calls в Ollama через парсинг блоков. Это открывает возможность использовать любую модель, генерирующую структурированный вывод.

Проект полностью самодостаточен – не требует интернета, API-ключей, платных подписок.

Автор использует dogfooding: агент сам писал и коммитил свой код – хороший показатель доверия к продукту.

Реализован семантический поиск (RAG) на локальных эмбеддингах – редкость для подобных DIY-решений.

9. Итоговая оценка
Общая оценка: 8.5 / 10
(Отлично, но есть потенциал для улучшения)

Вердикт:
Проект является рабочим, продуманным и надёжным решением для локальной AI-помощи в разработке. Он успешно решает задачу замены облачных сервисов, предоставляя богатый набор инструментов, безопасность и удобный интерфейс. Архитектурный приём с prompt-based tool calling – изящный и практичный. Несмотря на некоторые архитектурные недочёты (отсутствие сессий, монолитность), для личного использования или небольшой команды проект полностью готов. Рекомендуется к использованию и может служить отличной базой для дальнейшего развития (мультиагентность, web-поиск, память между сессиями).

Особо ценные качества:

Полная офлайн-работоспособность.

Безопасность (бэкапы, подтверждения, верификация).

Хорошая документация.

Интеграция с RAG.

Рекомендации на ближайшее:

Внедрить сохранение сессий (хотя бы в локальный JSON).

Добавить возможность загружать файлы через UI.

Расширить список поддерживаемых языков для RAG.

Перейти на асинхронный код для повышения отзывчивости.
