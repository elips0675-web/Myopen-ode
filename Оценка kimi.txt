По критериям
Таблица
Критерий	Балл	Комментарий
Архитектура и код	8/10	Отличная модульность (agent.py + tools.py + rag.py + ui.py). Prompt-based tool calling — рабочее и понятное решение для 7B-моделей. Но run_agent_loop монолитен (~120 строк), подсчёт токенов приблизительный (len/4), а контекст суммаризуется только в начале — между 12 итерациями он может разрастись.
Функциональность	9/10	15 инструментов, RAG, сессии, мультиагентность (planner + executor), web search, fallback API, drag-and-drop, управление моделями. Для solo-проекта — фантастика.
Безопасность	7/10	Confirm-диалоги, бэкапы (50 версий), verify — хорошо. Но нет sandbox для bash, нет валидации путей на directory traversal (хотя Path используется), нет rate limiting, нет аутентификации. Любой с локальной сети может писать файлы.
UX/UI	7/10	Zero-dependency HTML — мудрое решение для «запустил и работает». Но inline-UI без npm ограничивает интерактивность (нет Monaco/CM для редактора, diff — только текстовый).
Потенциал	9/10	Это рабочая замена Cursor/Claude Code для локального использования. С добавлением MCP-протокола или нативного tool calling (когда Ollama поддержит) проект вырастет сильно.
Что впечатляет
Prompt-based tool calling — вы решили проблему отсутствия native tool_calls в Ollama для 7B-моделей. Это не костыль, а архитектурное решение, и оно работает.
RAG на nomic-embed-text — семантический поиск по codebase в локальном агенте — редкость даже в коммерческих продуктах.
Multi-agent — разделение планирования (1.5B) и исполнения (7B) экономит VRAM и ускоряет простые задачи.
Self-healing — verify после write/edit, auto-commit, undo. Агент действительно заботится о целостности кода.
Memory между сессиями — .agent_memory/ с суммаризацией через лёгкую модель. Это уже близко к «персональному ассистенту», а не просто чату.
Что можно улучшить (приоритетно)
Суммаризация внутри loop — сейчас summarize_context вызывается один раз перед циклом. Если агент делает 10 итераций, история разрастается. Нужно суммаризировать каждые 3-4 итерации.
Точный подсчёт токенов — len(content) / 4 — очень грубо. Можно использовать tiktoken (для fallback) или эвристику по модели, или хотя бы считать токены ответа Ollama (в /api/generate есть eval_count в ответе, если не stream).
Sandbox для bash — сейчас bash выполняет всё от имени пользователя. Для деструктивных команд (rm -rf, curl | sh) стоит добавить чёрный список или dry-run режим.
Валидация путей — write/edit с ../../etc/passwd теоретически может выйти за WORK_DIR. Нужна проверка Path.resolve().is_relative_to(WORK_DIR).
Graceful degradation — если Ollama упал во время loop, агент просто сломается. Нужен retry с exponential backoff для call_ollama.
Итог
Это рабочий, production-ready pet-project с архитектурой уровня стартапа. Он решает реальную проблему (хочу Cursor, но без облака и подписок) и делает это элегантно.
Рекомендация: добавьте нативный tool calling, как только Ollama выпустит стабильную поддержку для small models, — и это станет серьёзным open-source конкурентом Cody/Windsurf в нише local-first development.
Итоговая оценка: 8.0 / 10 — «отличный инженеринг с потенциалом стать экосистемой».
