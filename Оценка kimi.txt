Оценка проекта My OpenCode
Проект выглядит очень достойно для самостоятельной разработки локального AI-агента. Ниже разбор по критериям и итоговая оценка.
1. Архитектура и код — 8/10
Плюсы:
Один файл agent.py (~600 строк) — впечатляющая компактность. FastAPI + SSE + inline HTML + agent loop + RAG + git + бэкапы — всё в одном месте. Это осознанный выбор для zero-dependency setup, и он работает.
Prompt-based tool calling — креативное решение проблемы: qwen2.5-coder:7b не поддерживает native tool_calls, поэтому вы заставили модель выводить ```tool блоки. Это рабочий паттерн, проверенный вами на практике.
Автосуммаризация контекста — умный ход: когда история >4K, старые сообщения сжимаются через 1.5b модель. Это критично для 32K окна.
RAG через Ollama embeddings — cosine similarity на чанках кода (разбивка по def/class) — прагматично и рабоче.
Минусы:
Монолит — один файл хорош для старта, но при росте (мультиагентность, memory, web search) станет тяжело. Нет разделения на слои (API / agent / tools / UI).
Глобальные переменные (RAG_INDEX, RAG_CHUNKS, RAG_DIRTY) — для продакшена лучше инкапсулировать в класс.
Валидация JSON — validate_tool слишком простая, не проверяет типы полей глубоко (только path и content). extra проверка выглядит незавершённой.
Обработка ошибок — много except: pass, особенно в RAG и embeddings. Если Ollama упадёт, агент молча продолжит без RAG.
2. Функциональность — 9/10
Плюсы:
14 инструментов — покрывают 95% задач AI-агента: чтение, запись, редактирование, bash, поиск, git, веб, verify, undo, plan, RAG.
Verify — автопроверка синтаксиса (py_compile, tsc, json.tool) сразу после write/edit. Это редкость даже в коммерческих продуктах.
File versioning — до 50 бэкапов с undo. Практически спасает от ошибок модели.
Plan tool — модель предлагает план, пользователь подтверждает. Это правильный UX для сложных задач.
Параллельный tool calling — поддержка нескольких ```tool блоков в одном ответе.
Минусы:
Stateless сессии — история чата хранится только в памяти frontend'а. Перезагрузка страницы = потеря контекста. Это критично для серьёзной работы.
Нет лимита по токенам — только 12 итераций и 60s timeout. Для больших рефакторингов может не хватить.
Нет управления моделями — нельзя pull/delete модели через UI.
WebSearch отсутствует — пока только web (fetch URL). Поиск по Google/DDG не реализован.
3. Безопасность — 8/10
Плюсы:
Конфирмация перед write/edit/bash/commit/undo. Это must-have для AI-агентов.
Бэкапы перед каждой деструктивной операцией.
Timeout'ы — 60s на цикл, 15s на verify, 30s на grep.
JSON Schema валидация — проверка обязательных полей.
Минусы:
bash без sandbox'а — команды выполняются напрямую в shell. Хотя есть конфирмация, случайное "yes" на вредоносную команду (или jailbreak модели) может навредить. Для локального использования приемлемо, но для shared-среды — риск.
Нет ограничения на пути — write может писать куда угодно (хотя WORK_DIR дефолтный). Абсолютные пути (C:/...) поддерживаются без вайтлиста.
RAG читает всё подряд — .env, конфиги с секретами попадут в индекс, если лежат в рабочей директории.
4. UX/UI — 7/10
Плюсы:
Zero npm — inline HTML/CSS/JS, работает из коробки. Переключение тем, статус Ollama, SSE-стриминг.
Diff view — подсветка +/-/@@ в чате.
Cancel — AbortController для прерывания генерации.
Тёмная тема с сохранением в localStorage.
Минусы:
UI минималистичный — нет файлового дерева, нет подсветки синтаксиса в code blocks (только <pre><code>), нет табов для нескольких файлов.
Нет истории чатов — один тред, нельзя создать новый без перезагрузки.
Нет drag-and-drop — нельзя скинуть файл в чат или загрузить картинку.
Модель выбирается в <select>, но нет индикации, какая сейчас используется в сессии.
5. Потенциал и дорожная карта — 9/10

Топ-3 приоритета для улучшения
Сохранение сессий — записывать историю чатов в SQLite/JSON на диск, с возможностью продолжить после перезагрузки. Сейчас это самая болезненная точка.
Рефакторинг agent.py — вынести tools, RAG, UI в отдельные модули. Монолит на 600 строк уже на грани.
File tree в UI — хотя бы простой sidebar со списком файлов проекта, чтобы не писать list/read вручную.
Проект заслуживает звезды на GitHub. Для одного разработника на RTX 3060 — это выдающийся результат.
