# My OpenCode — Руководство пользователя

Локальный ИИ-агент-программист на Ollama: работает бесплатно, полностью офлайн/приватно, как Cursor или Claude Code, но на вашей машине.

## Установка

1. **Установите Ollama** с https://ollama.com/download и запустите его.
2. **Скачайте модель для кодинга** (рекомендуется):
   ```
   ollama pull qwen2.5-coder:7b
   ```
   Для 12+ GB видеопамяти можно `deepseek-coder-v2:16b`.
3. **Установите Python 3.11+** и зависимости проекта:
   ```
   pip install -r requirements.txt
   ```
4. **Запустите агента**:
   ```
   python agent.py
   ```
   Браузер откроется на http://localhost:8765. Можно запустить нативное окно:
   ```
   python desktop.py          # окно pywebview (иконка, авто-старт сервера)
   python desktop.py --browser
   ```
   Или без интерфейса, одной командой (без подтверждений):
   ```
   python -m myopencode "создай файл hello.py с функцией greet"
   ```

## Первый запуск

1. Введите в чат что-то простое: «Что ты умеешь?» — агент ответит без вызова инструментов.
2. Скажите: «Создай файл hello.py с функцией greet» — агент создаст файл в текущем проекте.
   - На вопрос подтверждения (`[CONFIRM] Allow write?`) ответьте **yes** (или «да»).
3. Проверьте дерево файлов слева — hello.py появился.

## Как задавать задачи

| Задача | Пример | Что сделает агент |
|---|---|---|
| Создать файл | «Создай hello.py с функцией greet» | write → verify |
| Найти баг | «Почему падает скрипт main.py?» | read → bash (python main.py) → edit |
| Запустить код | «Запусти тесты» | bash (pytest) → отчёт |
| Поиск по коду | «Где определена функция load_config?» | search/grep → ответ |
| Рефакторинг | «Переименуй foo в bar в app.py» | read → edit → verify |
| Интернет | «Найди актуальную версию Flask» | websearch → ответ |

Полезные инструменты UI:
- **Файловое дерево** слева — просмотр/открытие файлов.
- **Вкладки** поверх чата — редактор с подсветкой (Ctrl+S сохранить, Ctrl+Space автодополнение).
- **Слэш-команды**: `/test` (прогнать тесты), `/fix` (найти и исправить ошибки), `/review` (ревью изменений), `/doc` (сгенерировать документацию), `/deploy` (план деплоя).
- **@сабагенты (прямые маркеры)**: `@reviewer <задача>` (ревью кода), `@fixer <задача>` (исправить найденное), `@general <задача>` (агент-исследователь) — первое слово сообщения запускает соответствующий сабагент со своим промптом и выводом отчёта в формате ревью (`CRITICAL:/WARNINGS:/VERDICT:`). Тот же эффект — кнопки 🧐 Ревью / 🔧 Фикс / 🧭 Агент над полем ввода.
- **@агенты (через модель)**: `@explore` (исследование кода), `@scout` (веб-исследование) — модель сама решает, вызывать ли тул `task`.
- **Терминал** внизу — настоящий интерактивный терминал (xterm.js + WebSocket): запустите Python/CMD/PowerShell или команду, Ctrl+C — прервать, New shell / Kill / Clear.
- **Сессии** — переключение между задачами, история сохраняется автоматически (SQLite).
- **Модели** — смена модели (⚙ → Models), pull новых.

## Как это работает (коротко)

Агент работает в цикле: получает вашу задачу → **вызывает инструменты** (read/write/edit/bash/grep/...) → анализирует результат → снова вызывает → ... → выдаёт итоговый ответ. Для моделей, поддерживающих нативный tool calling (qwen3, llama3.1, gpt-oss), агент использует `tools=`-параметр Ollama; для остальных — специальные ```` ```tool {JSON} ```` блоки («ручной» аналог tool calling, работает даже на 7B-моделях). Переключение автоматическое.

Подтверждения: опасные операции (запись файлов, edit, bash, commit) требуют вашего `yes` — это защита. Если хотите авто-подтверждение — запустите с `NO_CONFIRM=1` (только для доверенных проектов!).

**Пакетный режим «yes all»:** для длинных задач с множеством файлов (web-приложение, проект целиком) ответьте `yes all` (или «да всё», `go all`) на первый вопрос `[CONFIRM]` — текущая операция выполнится, и **все дальнейшие** write/edit/bash/commit/undo в этой сессии пройдут без подтверждений (флаг действует до конца сессии; подсказка и нумерация `(session confirm #N)` видны в ответе). Чтобы убрать флаг — начните новую сессию.

## Десктоп-обёртка (Tauri / pywebview)

Есть два способа запустить нативное окно (обе обёртки сами стартуют сервер,
если он не запущен, и переиспользуют уже работающий):

| Способ | Что нужно | Команда |
|---|---|---|
| **Tauri (WebView2)** | Rust + MSVC Build Tools (одноразовая установка) | `scripts\run_tauri.bat` (первый запуск компилирует обёртку, дальше — мгновенный старт) |
| **pywebview** | `pip install pywebview` | `python desktop.py` (флаг `--browser` — открыть в браузере) |

Установка тулчейна для Tauri (Windows):

```
winget install Rustlang.Rustup -e
winget install --id Microsoft.VisualStudio.2022.BuildTools -e --override "--quiet --wait --norestart --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
# в новом терминале: rustup default stable
```

Обёртка Tauri: окно WebView2 1280×860 с иконкой, URL `http://127.0.0.1:8765`.
Полезные env: `MYOPENCODE_PORT` (порт, по умолчанию 8765), `MYOPENCODE_PYTHON`
(интерпретатор для автозапуска сервера).

## Что делать, если...

### Модель не отвечает
1. Проверьте, что Ollama запущен: http://127.0.0.1:11434/api/tags
2. Проверьте установленную модель: `ollama list`
3. Посмотрите консоль сервера (`.server_err.log`) — там видно ошибки запросов.
4. Слишком долгий первый ответ — модель грузится в память (1-2 мин). Дальше — быстрее.

### Агент зациклился / отвечает мусором
- Нажмите **Cancel** в чате — цикл остановится.
- Не подтверждайте `[CONFIRM]` — цикл завершится после break.
- Задайте задачу проще и конкретнее; 7B-модели лучше работают с маленькими шагами.
- Убедитесь, что выбрана qwen2.5-coder (deepseek-r1:7b нестабильна в tool-формате).

### Тулы «не работают» / файлы не находятся
- Агент работает только внутри `WORK_DIR` — файлы вне его недоступны по дизайну.
- После `write` он обязан проверить файл сам; если этого не произошло — попросите: «проверь файл, который ты создал».
- Если агент «галлюцинирует» пути — скажите: «используй list/glob, не выдумывай пути».

### Ollama не видит GPU
- Проверьте: `ollama ps` — модель должна быть на GPU (показывает размер VRAM).
- Windows: установите драйвер CUDA/ROCm, перезапустите Ollama.
- Если модель больше VRAM — она уйдёт на CPU (это нормально, но медленно в 5-10 раз).

### Не сохраняются сессии
- Проверьте права на запись в папку проекта (файл `sessions.db`).

## Как добавить свой skill

1. Создайте файл `.agent_skills/<имя>.md` в папке проекта:
   ```markdown
   # <Имя> — что делает этот скилл
   ## Когда применять
   ...
   ## Инструкции
   Шаг 1: ...
   Шаг 2: ...
   ```
2. В чате: `@skill <имя>` (или просто упомяните задачу — модель может выбрать скилл сама).
3. Скиллы — это Markdown-инструкции, которые добавляются в контекст модели.

## Как добавить свой инструмент (плагин)

Создайте `.agent_plugins/my_plugin.py`:
```python
def register(server):
    server.add_tool(
        name="my_tool",
        description="Что делает",
        args={"query": {"type": "string", "required": True}},
        handler=lambda args: f"результат для {args['query']}",
    )
```
Перезапустите сервер — инструмент появится в списке.

## Мобильный доступ

Откройте http://<IP-компьютера>:8765 с телефона (порт должен быть доступен в сети). Интерфейс адаптивен.

## Troubleshooting (расширенный)

- **«Error: attempted relative import»** — запускайте сервер из корня проекта: `python agent.py`.
- **Windows, кириллица в консоли** — установите `PYTHONUTF8=1`.
- **Всплывающее окно cmd при LSP** — старые версии; обновите с GitHub.
- **RAG-индексация падает** — удалите `rag_cache/` и перезапустите.
- **Всё ещё не работает** — откройте issue на https://github.com/elips0675-web/Myopen-ode с содержимым `.server_err.log`.
